# Midnight Korea Hackathon 2026 제출 안내

확인일: 2026-09-10. 공식 한국어 페이지와 버튼으로 열린 실제 Tally 폼을
확인한 기록이다. 일정과 폼은 바뀔 수 있으므로 최종 제출 직전에 재확인한다.
제출 요구 조사 자체가 아키텍처 승인을 뜻하지 않는다. 다만 2026-09-15에 사용자가
별도로 **IntelliJ 한 번 실행 / Railway 통합 앱 한 번 배포 / 가상 데이터 Preview
데모**를 승인했다. 현재 실행 지침은 루트 AGENTS.md와 ADR-023을 따른다.
실행 작업과 완료 여부는 [TODO.md](TODO.md), 현재 구현 상태는
[CONTEXT.md](CONTEXT.md)를 따른다.

## 핵심 목표와 사용자 결정

- 사용자가 2026-09-10에 Luma 등록 완료를 확인했다.
- 최종 목표는 **심사자가 공개 코드를 받아 빌드하고 핵심 Midnight 흐름을
  재현할 수 있으며, 실제 동작하는 데모와 구현 근거로 심사에 대응하는 것**이다.
- 사용자는 기존 GIWA GASOK 해커톤 프로젝트에서 Midnight 브랜치로 고도화한
  이력을 고려해 Midnight 제출용 새 공개 저장소를 준비하는 방향을 제시했다.
  기존 제출물을 그대로 재제출한 것으로 오해받지 않도록 별도 소개와 명확한
  기여 설명이 필요하다. 2026-09-15 후속 지시로, 기능 작업을 더 진행한 뒤
  최종 제출 전에 필요한 소스를 일반 폴더로 담은 단일 공개 저장소와 `main`
  제출 버전을 준비하는 방향을 기록했다. Vercel 이름·주소 정리도 그때 진행한다.
  이름·소유자·공개 파일/이력 범위는 아직 미정이며 실제 전환은 수행하지 않았다.
  상세 작업은 [최종 저장소·주소 체크리스트](MIDNIGHT_RELEASE_CHECKLIST.md)를 따른다.
- 새 저장소 자체는 공식 필수 조건이 아니다. 공식 요구는 Public GitHub다.
  새 이름이나 저장소만으로 신규성이 입증되거나 기존 코드 재사용이 허용되는
  것은 아니다. GASOK 기반 코드, 이미 존재하던 Midnight 구현, 이번 대회 기간에
  실제 추가·변경한 부분을 구분하고 출처·라이선스·기여 이력을 설명한다.
- 이번 문서 반영은 원격 저장소 생성, 공개 전환, push, Git 이력 삭제 또는
  대회 제출을 수행한 것이 아니다.

개인 연락처와 팀원의 이메일은 제출 폼용으로 준비하며 이 공개 문서에 적지 않는다.

## 심사 대응 기준

공식 페이지는 다음 검토 과정을 명시한다.

1. 저장소를 클론해 컴파일한다.
2. 제출 폼과 README 설명이 일치하는지 확인한다.
3. Midnight 기능이 명확히 드러나는지 평가한다.
4. 데모를 확인할 수 있는지 검토한다.

이를 위한 프로젝트 완료 기준:

- 제출할 정확한 커밋을 깨끗한 환경에서 클론해 필수 소스를 모두 확보한다.
  현재 루트는 `giwa-ui`, `giwa-api`, `giwa-contrract`, `giwa-midnight`를
  서브모듈로 참조한다. 루트 공개만으로 내부 코드가 함께 공개되는 것은 아니다.
  2026-09-15 후속 계획은 필요한 소스를 새 저장소의 일반 폴더로 모으는 것이다.
  최종 저장소의 일반 클론에서 모든 필수 코드를 확보하고 빌드되는지 확인하며,
  통합할 때 원래 출처와 라이선스를 보존한다. 실제 통합은 최종 제출 준비 때 진행한다.
- README에 도구/버전, 의존성 설치, 환경변수 예시, Local Devnet 초기화,
  Compact 컴파일, 로컬 계약 배포·Provider 등록, 각 서비스 실행 순서,
  DB 준비, 데모 계정/역할/지갑 준비, 기대 결과와 문제 해결 절차를 제공한다.
- 기존 작성자의 ignored 상태·DB·지갑·로컬 계약 주소에만 의존하지 않도록
  새 로컬 환경을 준비하는 절차와 필요한 GIWA 테스트넷 의존성을 검증한다.
  비밀값은 실행자가 로컬에서 생성/주입하며 공개 저장소에 포함하지 않는다.
- 실제 CLI 확인을 기반으로 Vue v2 전체 흐름과 유효한 `true`/`false` 결과를
  확인한다. 과거 로그·단위 테스트·컴파일 성공만으로 현재 E2E 완료를 선언하지 않는다.
- 짧은 영상에는 문제, 사용자 동의, 증명 진행, 기준과 최종 결과를 보여준다.
  실제 증명 대기 구간을 편집했다면 표시하고 실행 시간과 원본 근거를 남긴다.
- 증명 실패·거절·만료와 유효한 기준 미충족 결과를 구분해 설명하고, 프라이버시
  범위·mock 한계·기존 코드 대비 기여를 README/Deck/폼/영상에서 일치시킨다.

## 현재 GASOK Midnight 흐름으로 설명할 내용

현재 기준은 [MIDNIGHT.md](MIDNIGHT.md)의 request-bound v2다.
아래는 설명할 구현 흐름이며, 이번 조사에서 런타임을 재검증한 결과는 아니다.

1. Funder가 대상 채권/역할과 공개 기준·기한을 요청하고 Spring이 요청을 관리한다.
2. 해당 Seller/Buyer가 요청을 검토하고 mock 재무값과 역할 지갑 동의를 제공한다.
3. 로컬 Mock Provider가 동의를 확인하고 입력·문맥에 서명한다.
   이는 은행이나 회계기관에서 받은 재무정보의 진실성을 검증하는 단계가 아니다.
4. Compact가 Provider 서명과 요청에 묶인 기준을 검사한다. 로컬 Proof Server는
   private witness로 ZK 증명을 생성하고 Midnight Node는 트랜잭션을 검증·기록한다.
5. Bridge가 결과 capability를 보존하고 Vue/Spring이 전달을 조율한다.
   Funder는 Read API/Indexer로 공개 결과를 확인한다. Indexer 지연은 읽기 재시도로
   처리하며 새 proof를 반복 제출하지 않는다.

재무 원문은 MySQL·공개 ledger에 저장하지 않는다. 공개 결과는 opaque key 아래
결합된 기준 충족 여부와 Provider/버전/시점/만료 메타데이터다. 세부 공개 범위와
한계는 현재 프로토콜 문서와 대조한다. Proof Server와 Bridge 등 로컬 구성요소의
신뢰 범위까지 설명하며 “어느 누구도 원문을 보지 않는다”고 주장하지 않는다.

GIWA는 계속 채권 토큰화·펀딩·상환·자산 이동을 담당한다. Midnight 결과는
mock-attested 기준 충족 여부이지 은행 검증, 자동 펀딩 승인 또는 Funding gate가 아니다.
폼·README·데모에서 수동 JSON/PIN을 사용하는 과거 v1을 현재 제품 흐름으로 소개하지 않는다.

공식 페이지는 **Local Devnet을 허용**한다. 기존 로컬 실행 방식을 유지하며
Midnight Preprod/Mainnet 배포나 로컬 Bridge의 외부 공개를 제출 요건으로 추정하지 않는다.
공개 데모 URL은 선택이고, 로컬 환경에서도 심사자가 실행·확인 가능한 안내가 필요하다.

## 아직 확인해야 할 사항

- 기존 해커톤 제출 코드와 대회 시작 전 Midnight 구현의 재사용 허용 범위,
  신규 작업 기간과 기여 표시 기준. 공개 페이지/폼만으로 허용 여부는 확정하지 않았다.
  필요하면 주최 측에 기존 이력과 이번 변경 범위를 설명해 확인한다.
- 저장소 이름·소유자·공개 범위·구성, 제출 커밋과 데모에 포함할 기능.
- 제출 후 수정 허용 여부, 최종 폼의 항목·일정 변경 여부.
- 이 기록은 프로젝트가 제출되었거나 심사 자격·현재 데모 동작이 검증됐다는 뜻이 아니다.
